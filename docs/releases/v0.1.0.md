# Behavior Suite v0.1.0 — Internal Laboratory MVP

**Release date:** 2026-10-29  
**Scope:** Internal research MVP for Windows laboratory use (Subsystems **S1–S10**).  
**Not a public product release.** Not a claim of full legacy Pipeline numerical/biological parity.

---

## Summary

v0.1.0 packages the completed S1–S10 GUI workflow (Groups 1–4) for Engelhard Lab internal use: prepare video → pose → tracking → finalization → blob/combined features → behavioral inference → arbitration → results packaging/export → behavioral review/publication.

Operator laboratory acceptance is recorded through S10 (S9/S10 signed 2026-10-29). See [`s1_s10_mvp_readiness.md`](s1_s10_mvp_readiness.md) for the audit and final verification evidence.

---

## Supported environment

| Item | Support |
| --- | --- |
| OS | Windows lab/developer workstation |
| Install | `scripts\install_windows_gui.bat` → env `behavior_suite_gui` |
| Launch | `scripts\launch_windows_gui.bat` |
| Runtime | Python 3.12, FFmpeg 7.1.1, PySide6 6.11.1 (conda-forge) |
| Extras | Editable `.[s2,s7]` (`sleap-io==0.8.0`; xgboost / scikit-learn / joblib) |

**External (not installed by the suite installer):**

- SLEAP-NN **0.3.x** executable with `predict` (lab-validated **0.3.0**)
- Lab-local SLEAP **inference** model directories (selected in S2)
- S7 detector registry root → typically repo `models/` (`dyadic/v1`, `focal/v1`)
- Writable session/project directory (prefer local disk; UNC may need verification)

Full checklist: [`installation_prerequisites.md`](installation_prerequisites.md).

## S1–S10 capabilities

| Group | Subsystems | Operator-facing capability |
| --- | --- | --- |
| 1 — Data Preparation | S1–S4 | Preprocess; SLEAP pose inference; tracking review/accept; dense pose finalization |
| 2 — Feature Processing | S5–S6 | Blob/video features; combined dyadic features |
| 3 — Behavioral Inference | S7–S8 | Detector inference; ethogram arbitration + bouts |

Headless runners exist for each subsystem under `src/`. GUI navigation is Groups 1–4 in `behavior-suite gui`.

## Known limitations (ship with release)

**P1**

- No single continuous **fresh full-length** S1→S10 acceptance recording (E-session is multi-date staged). Short-clip fresh smoke remains recommended follow-up.
- `behavior-suite doctor` does not verify SLEAP-NN or the S7 registry.
- Large Git LFS SLEAP training media under `models/SLEAP/` is optional for inference and burdens clones.
- No in-repo CI; regressions rely on local pytest.
- Pipeline 50 numerical parity and ethogram ground-truth validation are **unverified**.
- Historical S7 manifests under `legacy/models/...` can mark downstream packages stale until digests resolve (junction/remap or new runs with `models/`).
- Stale pytest assertion vs `/test_cases/` gitignore pattern; S10 E-session “no published review” tests fail once a lab-accepted review exists (environmental).

**P2 (deferred)**

- Cooperative cancellation; K>2 animals; S8 overlay video; S10 reviewed media/CSV re-export; reciprocal edit / `uncertain` status.
- Auto-continue navigation polish after S3→S4 and later stages.
- Richer doctor checks; LFS training-asset cleanup; accidental `models/SLEAP/New folder/` duplicate.

---

## Legacy compatibility qualifications

- Modern suite stages map to legacy Pipeline roles (prepare / pose / correct / finalize / blob / dyadic features / inference / arbiter / packaging / review) but **are not bit-identical**.
- Documented S8 deviations from Pipeline 100 are preserved (invalid evidence, `undefined`, no contact remultiplex; Stage 8 morph-close disabled at `max_gap_to_fill=0`).
- S6 vendored formulas; numerical regression vs training caches deferred.
- Do **not** claim biological ground-truth accuracy of ethogram labels from S9/S10 acceptance (controlled edits / packaging only).

## Installation

From the repository root on a supported Windows machine:

```bat
git pull
scripts\install_windows_gui.bat
scripts\launch_windows_gui.bat
```

Then configure S2 SLEAP models and S7 registry (`models/`) as described in [`installation_prerequisites.md`](installation_prerequisites.md).

Package version in `pyproject.toml`: **0.1.0**.
