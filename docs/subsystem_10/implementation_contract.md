## 3. Inspection and synchronization contract

### 3.1 Coordinate and index conventions (frozen)

| Name | Domain | Range / grain | Authority |
| --- | --- | --- | --- |
| `sample_idx` | Dense analysis index | Contiguous `0 … N_dense-1`; **≡** `dense_frame_idx` | S9 `sync_index` / S8 |
| `time_sec` | Analysis clock | Uniform 120 Hz target time | S4/S5/S8 |
| `prepared_frame_idx` | Prepared video decode index | `0 … N_prep-1` | S1 `prepared_sync` via sync_index |
| `prepared_time_sec` | Prepared clock | At mapped prepared frame | sync_index |
| Bout endpoints | Inclusive dense samples | `[start_sample_idx, end_sample_idx]` | S8/S9 bouts |
| `bout_duration_frames` | Inclusive count | `end - start + 1` when contiguous | Never unique-prepared counts |
| `bout_duration_sec` | Duration | `bout_duration_frames / 120` | Never `end_time - start_time` alone as authority |

**Playhead state (session):**

```text
playhead.sample_idx : int64          # behavioral authority
playhead.time_sec   : float64        # = sync_index.time_sec[sample_idx]
playhead.prepared_frame_idx : int64  # = sync_index.prepared_frame_idx[sample_idx]
playhead.prepared_time_sec  : float64
```

### 3.2 Dense 120 Hz playhead and prepared-frame mapping

| Concern | Rule |
| --- | --- |
| Advance / scrub / step | Operate on **dense** `sample_idx` (or dense time → nearest sample) |
| Video decode | `read_raw_frame_at_index(prepared_video, prepared_frame_idx)` (or thin prepared wrapper that calls it) |
| Identity seek verification | Required for scientific seeks; unverified `CAP_PROP_POS_FRAMES` alone is insufficient |
| Bout jump start/end | Use packaged `prepared_frame_idx_start/end` **or** equivalent sync lookup at inclusive endpoints |
| UI clock labels | Always distinguish “analysis time” vs “prepared video time” |

### 3.3 Many-to-one plateaus

**Fact:** Multiple consecutive `sample_idx` may share one `prepared_frame_idx`.

| Policy | Specification |
| --- | --- |
| Playhead | Advances by dense sample even when prepared index is unchanged |
| Video pixmap | Keep last decoded frame when prepared index unchanged; still refresh ethogram/evidence cursors |
| Primary scrubber | Dense timeline |
| Secondary indicator | Read-only prepared-frame / prepared-time |
| Click-on-video / prepared scrub | Map prepared time → candidate dense samples on that plateau; select dense sample nearest in `time_sec`; **tie-break: earlier `sample_idx`** |
| Short bouts on plateaus | Inclusive dense endpoints remain valid even if start and end share one prepared frame — do not expand/collapse science to unique frames |
| Playback scheduler | Tick on dense time; request decode only when prepared index changes; cache by `prepared_frame_idx` |

### 3.4 Playback, seeking, bout navigation

| Action | Semantics |
| --- | --- |
| Play / pause | Dense-time scheduler; speeds are UI multipliers on analysis clock |
| Step ±1 | `sample_idx ± 1` (clamp to `[0, N_dense-1]`) |
| Jump to sample / time | Exact sample or nearest sample by `time_sec` (earlier on ties) |
| Jump to bout start/end | Set playhead to inclusive endpoint sample; decode mapped prepared frame |
| Prev/next bout | Within **active navigation set** (full science table by default; optional `review_emit_v1` or user view filters) |
| View filters | Hide rows in UI only; log in session UI state; **never** rewrite automated tables |

One workspace, linked surfaces:

| Surface | Content |
| --- | --- |
| Video pane | S1 `prepared_video.mp4` still/play frames |

**U8:** optional UI grouping of reciprocal exclusive siblings is allowed; science rows remain directional.  
**U9:** I/NI role badges optional, display-only.

## 4. Editing architecture (framewise-authoritative)

### 4.1 Channel model

| Channel | Grain | Editable field | Invariant |
| --- | --- | --- | --- |
| Exclusive | `(sample_idx, focal_id, partner_id)` | `behavior_label` (+ synced exclusive `pred_*` derived for display consistency) | Exactly one exclusive label per cell |
| Contact | `(sample_idx, mouse_a_id, mouse_b_id)` undirected | `pred_contact` ∈ {0,1} | Independent of exclusive |
| Side-by-side | same undirected | `pred_side_by_side` ∈ {0,1} | Independent of exclusive; never promoted to exclusive |

Allowed exclusive labels (S8):  
`nose_to_nose`, `nose_to_body`, `nose_to_tail`, `approach`, `retract`, `mutually_disengaged`, `engaged`, `undefined`.

Parallel positives may coexist with any exclusive label.

### 4.2 Baseline and working states

| Layer | Mutability | Source |
| --- | --- | --- |
| Automated baseline states | Immutable | S8 `behavior_states.parquet` (via S9 reference/embed) |
| Automated baseline bouts | Immutable | S9 `behavior_bouts.parquet` |
| Working reviewed states | Mutable projection | Baseline ⊕ applied correction events (up to journal cursor) |
| Working reviewed bouts | Derived | Pure collapse of working states (U11) |
| Review-status / notes | Independent overlay | Separate events / tables (§5) |

### 4.3 S8 collapse reuse (U11) — what may be called

**Allowed (pure, no science rewrite of automated runs):**

- `behavioral_arbitration.bouts.extract_behavior_bouts`
- Internal helpers it uses: `_contiguous_segments`, `_extract_exclusive_bouts`, `_extract_parallel_bouts`, `_bout_row`, …

**Forbidden during reviewed regeneration:**

- Hierarchy conflict resolution / decay  
- Adaptive movement stages  
- Contact optical assist / Schmitt / morphological gap / min-bout cleaning  
- Temporal stitch / rescue / reciprocity / hysteresis  
- `finalize_behavior_labels` scientific promotion rules (except: reviewed states already carry explicit labels the operator set; collapse only segments those labels)  
- Pipeline 110 emit floors / presentation filters  

**Collapse rules reused as-is:**

1. Exclusive: per `(exp_name, focal_id, partner_id)`, sort by `dense_frame_idx`; split when `behavior_label` changes **or** dense gap ≠ 1.  
2. Parallel: undirected dedupe to one row per `(pair, dense_frame_idx)`; positive-only contiguous `pred_*=1` segments.  
3. Inclusive endpoints; `bout_duration_frames = len(block)`; `bout_duration_sec = frames / 120`.  
4. Contact/SBS `focal_id`/`partner_id` null; exclusive directional IDs required.

If shared extraction is needed to avoid importing full S8 package side effects, S10 may extract a **pure** collapse module that is behavior-identical to `bouts.py` without changing S8 published outputs.

### 4.5 Interval semantics

| Rule | Spec |
| --- | --- |
| Inclusivity | All correction intervals are inclusive on both ends in dense `sample_idx` |
| Empty | `end < start` is illegal (reject event) |
| Clamping | Out-of-range samples rejected; no silent clamp beyond `[0, N_dense-1]` |
| Exclusive write | Overwrites exclusive label on each sample in interval for that direction only |
| Parallel write | Overwrites pred on undirected pair samples; apply engine writes both directional state rows’ parallel columns consistently (S8 states are directional rows carrying parallel preds) |
| Gaps | Collapse splits on dense discontinuities; corrections do not invent missing sample rows |

### 4.6 Identity handling

| Edit | Identity binding |
| --- | --- |
| Exclusive | Exact `(focal_id, partner_id)`; opposite direction untouched unless reciprocal op |
| Parallel | `mouse_a_id=min`, `mouse_b_id=max`; never invent focal/partner on parallel bout rows |
| Active pair UI | MVP selects the session dyad; schemas keep pair_id for future K>2 |

### 4.7 Conflict rules

| Conflict | Resolution |
| --- | --- |
| Two exclusive labels on same cell | Impossible after apply — last **applied** event in journal order wins for that cell |
| Exclusive vs parallel | No conflict — independent channels |
| Status vs label | No conflict — independent (R7/R15) |
| Concurrent reviewers | MVP single-writer lock per working review (§6.6) |
| Event with unknown `op` / schema | Fail closed on apply; do not skip silently |
| Reciprocal + later one-sided edit | Allowed; later event wins per cell |

### 4.8 Edit ordering and apply engine

```text
working_states = copy(baseline_states)
for event in journal[0 : cursor]:
    apply(event, working_states)   # channel-isolated
working_bouts = extract_behavior_bouts(working_states, fps=120, ...)
```

| Rule | Spec |
| --- | --- |
| Order | Strict `event_seq` ascending |
| Idempotent rebuild | Replaying `journal[0:cursor]` always yields the same working states |
| Partial channel regen | Allowed optimization: regenerate bouts only for touched identities/channels — must match full collapse |
| Provenance columns | Corrections update labels/preds; do not fabricate S7 probs; may set `label_reconstruction="manual_review"` on touched exclusive samples |

### 4.9 Undo / redo (U14)

| Action | Behavior |
| --- | --- |
| Undo | Move cursor left by one `undo_group_id` (possibly multi-event); reapply |
| Redo | Move cursor right by one group if redo buffer intact |
| New edit after undo | Truncate redo side (linear history); append new events |
| Across restart | Cursor + journal persisted (§6) so undo/redo survives app restart |
| Reset to baseline | Explicit command: cursor → 0 (keeps journal for audit) or branch new working review — MVP: cursor→0 with session marker |

S3 has undo only; S10 **requires redo**.

### 4.10 Modes

| Mode | Capabilities |
| --- | --- |
| **Inspection** (default) | Play, scrub, timelines, evidence, bout jump, view filters; notes read-only if present |
| **Editing** | Explicit toggle; requires `reviewer_id`; enables correction tools + status tools |

## 5. Review status, notes, and progress (separated from edits)

### 5.1 Independent contracts

| Concern | Store | Does it change ethogram science? |
| --- | --- | --- |
| Label / interval corrections | Correction events → working states/bouts | **Yes** (reviewed layer only) |
| Bout acceptance / rejection | Review-status records / status events | **No** |
| Reviewer notes | Notes records / note events | **No** |
| Unreviewed | Default absence of decision | **No** |
| Uncertain | **Not in MVP** (U3) | — |
| Progress / completion | Derived counters + run lifecycle | **No** |

### 5.2 Per-bout status vocabulary (MVP)

| Status | Meaning |
| --- | --- |
| `unreviewed` | Default; no decision recorded |
| `accepted` | Reviewer accepts the **targeted interval identity** as reviewed-good |
| `rejected` | Reviewer rejects the targeted interval; row remains visible; **labels unchanged** (U15) |

### 5.3 Status attachment identity (binding)

Review status attaches to a **stable interval identity**, not to a transient UI selection:

**Primary key for automated (pre-edit) decisions:**

```text
status_target_kind = source_bout
(source_s8_bout_id, channel, package_run_id)
```

Optionally denormalize package `bout_id`, inclusive endpoints, behavior_name, identity fields for audit.

**After reviewed regeneration**, published status rows may also reference:

```text
status_target_kind = reviewed_bout
(reviewed_bout_id, channel, review_run_id)
```

plus optional `derived_from_source_s8_bout_id` when a 1:1 interval correspondence still holds.

**Interval key (for voiding):**

```text
(channel, identity_grain, focal_id|null, partner_id|null, mouse_a_id, mouse_b_id,
 behavior_name, start_sample_idx, end_sample_idx)
```

### 5.4 What happens after split / merge / delete / boundary change (R9)

| Geometry change affecting a status target | Status rule |
| --- | --- |
| Trim / split / merge / relabel that changes endpoints or `behavior_name` of a previously status-targeted interval | Prior `accepted`/`rejected` on that target becomes **`voided`** (or equivalent `stale_after_edit`) — **not** copied onto child bouts |
| Pure note edits | Status unchanged |
| Status-only reject/accept | Labels unchanged |
| New reviewed bouts created by collapse after edits | Start as **`unreviewed`** |
| Exact interval preserved (no sample label change in span; endpoints identical) | Status may remain attached to `source_s8_bout_id` |
| Operator re-accepts after edit | New status event on new interval identity / reviewed bout id |

**Forbidden:** silently transferring `accepted` from a source bout to multiple post-split children, or to a merged longer bout.

### 5.5 Notes

| Field | Spec |
| --- | --- |
| Attachment | Prefer `source_s8_bout_id` and/or `undo_group` / playhead sample range; allow free notes on review run |
| Editability | Editable in edit mode; read-only in inspection |
| Publication | Snapshot into published notes / status table |

### 5.6 Run-level review lifecycle

| Status | Meaning |
| --- | --- |
| `not_started` | Inspection only / empty working review |
| `in_progress` | Working journal and/or statuses exist; not published accepted |
| `published_accepted` | Immutable reviewed run published |
| `superseded` | Newer accepted publish exists for same parent lineage (discovery classification; do not rewrite old meta status arbitrarily — mirror S9 pattern: historical status preserved; discovery classifies) |

Opening a package ⇒ at most `not_started` inspection. Never `published_accepted`.

### 5.7 Progress metrics (derived, not science)

- Counts of bouts by channel × status (using current non-voided status map)  
- Fraction of exclusive samples touched by corrections  
- Last reviewer_id / timestamp  
- Navigation filter settings (UI state)

## 6. Working-state persistence and recovery

### 6.1 Working directory and identity

```text
{session_root}/behavioral_review/
  behavioral_review__{timestamp}/           # review_run_id
    review_manifest.json                    # draft or published
    settings_used.yaml
    run_meta.json
    processing_log.txt
    working/                                # mutable while in_progress
      working_manifest.json
      correction_events.jsonl               # append-only journal
      journal_cursor.json                   # cursor + redo_high_water
      review_bout_status.parquet            # or status_events.jsonl
      notes.parquet                         # optional
      locks/writer.lock                     # single-writer
      snapshots/                            # optional periodic state snapshots
    # published artifacts appear at run root after accept (§7)
```

| Field | Rule |
| --- | --- |
| `review_run_id` | `behavioral_review__YYYYMMDDTHHMMSS` |
| Parent pin | `parent_package_run_id` + package digests + `source_s8_run_id` + states/bouts digests at open/create |
| Draft vs published | `run_meta.publication_state ∈ {draft, published, failed}` |

Creating a working review is an **explicit** user action (“Start review” / first edit). PassiveInspection open must not create a draft automatically that looks accepted.**

### 6.2 Append-only event journal

| Property | Spec |
| --- | --- |
| Format | JSONL (MVP) with optional parquet snapshot at publish |
| Write | Append event → fsync → update cursor file via temp→rename |
| Read | Replay from start or from last validated snapshot + tail |
| Corruption | Length/checksum trailer or per-line schema validation; truncate to last valid event on recovery **after operator-visible warning** |
| Forbidden | In-place rewrite of historical events |

### 6.3 Save / recovery semantics

| Event | Behavior |
| --- | --- |
| Each successful gesture | Journal append + cursor update (crash-safe) |
| App crash | Reopen draft → validate parent pins → replay to cursor |
| Parent digest drift since draft create | Allow inspection of draft; **block further publish** (U12); optionally allow new corrections only after explicit “detach/rebind” policy — MVP: block publish, permit read-only recovery export of journal |
| Manual Save | Optional flush/snapshot; not required for durability if append path is sync |
| Discard draft | Explicit; does not delete published runs |

### 6.4 Undo/redo across restarts

Persist:

- full journal  
- `cursor_event_seq`  
- `redo_high_water_seq` (max seq still redoable)

Reopen restores undo/redo exactly.

### 6.5 Conflict and corruption detection

| Check | Action |
| --- | --- |
| Writer lock held by live process | Refuse second editor (MVP) |
| Stale lock | Operator-confirm break with audit marker |
| Journal gap / non-monotonic `event_seq` | Fail open of edit mode |
| Cursor > journal length | Clamp to last valid + warn |
| Schema version mismatch | Fail closed or migrate with explicit migrator (no silent) |

### 6.6 Multiple-reviewer policy (MVP)

| Policy | Spec |
| --- | --- |
| Writers | **Single writer** per `review_run_id` |
| Reviewer identity | Required string; recorded per event |
| Parallel reviews | Allowed as **separate** `behavioral_review__*` drafts on same parent package |
| Merge of two drafts | **Out of MVP** |
| Published authority | Explicit user selection among published reviews; never auto-pick “latest” without confirmation for downstream |

### 6.7 Drafts vs immutable published runs

| | Draft (`working/`) | Published run |
| --- | --- | --- |
| Mutability | Mutable journal | Immutable artifacts |
| Eligibility | Not a downstream analysis parent | Optional downstream parent via S10 eligibility API |
| Relation | May become published via atomic publish | Never rewritten; supersession via new run + discovery |

| --- | --- |

| `review_run_id` | Stamp |

- `publication_cursor_event_seq`

### 7.3 QC and eligibility

#### Structural blockers (fail publish)

- Parent S9 not currently eligible **or** digests drifted vs pins (U12)  
- Missing baseline states  
- Journal/cursor invalid  
- Reviewed states violate exclusive invariant  
- Reviewed bouts inconsistent with collapse(states)  
- Missing required artifacts after write  
- Writer identity missing  

#### Nonblocking warnings

- Parent S9 was `completed_with_warnings`  
- High fraction unreviewed  
- Voided statuses after edits  
- Optional S7 unavailable  

#### Explicitly not QC gates

- No biological purity thresholds  
- No mandatory 100% bout acceptance  
- No emit floors  

#### Discovery classifications

| Class | Meaning |
| --- | --- |
| `eligible` | Published completed(+warnings); parent pins still match; artifacts present |
| `stale_parent` | Review intact; parent S9/S8/video digests drifted |
| `draft` | In-progress working review |
| `failed_or_incomplete` | Publish failed |
| `superseded` | Newer eligible published review shares parent lineage (informational) |
| `missing_required_artifacts` | Core files absent |

Historical `run_meta.status` is not rewritten when eligibility changes.

### 7.4 Atomic publication and failure handling

Mirror S5–S9:

1. Validate draft + parent pins.  
2. Write science artifacts under temp or `running` state.  
3. Validate tables.  
4. Write `qc.json` / manifest.  
5. Promote `run_meta` to `completed` / `completed_with_warnings`.  
6. On failure: mark `failed`; delete/omit science tables as S9 does; preserve meta/log/settings; leave journal intact for retry.

Never mutate S8/S9 directories.

### 7.5 Downstream selection

| Consumer need | Selection |
| --- | --- |
| Automated analysis | Eligible S9 package (default) |
| Reviewed analysis | Explicit eligible S10 review run |
| Auto-pick latest reviewed | **Forbidden** without UI confirmation |
| S9 media/CSV | Remains automated-only in S10 MVP (U6) |

Both automated and reviewed outputs remain preserved and independently selectable.
